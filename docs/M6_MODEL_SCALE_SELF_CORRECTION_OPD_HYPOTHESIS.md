# M6 模型规模、自纠错与 OPD 性能演化假设

> 状态：研究假设与决策框架；不等同于训练准入，也不授权直接提交正式 OPD 或扩大训练。  
> 适用模型：Qwen3.5-4B Student、Qwen3.5-35B-A3B 候选 Specialist。  
> 核心目标：区分模型规模、SFT 数据、专项纠错、OPD 知识迁移和 Student on-policy GRPO 各自带来的增益，最终建立可复现的 `Raw < SFT < corrected/OPD < RL` 链路。

## 1. 问题定义

当前研究不把“更大的 Raw 模型”直接视为合格教师，也不把“SFT35 与 SFT4 点估计相近”解释为模型规模无效。需要分别回答五个问题：

1. Raw 模型规模是否带来稳定的零样本环境优势；
2. 在公平的 SFT 范式下，4B 和 35B 能否分别把成功轨迹转化为闭环能力；
3. 4B 能否仅靠专项数据构造、自纠错和 on-policy GRPO 超过 SFT35；
4. 若专项 SFT35 明确超过 SFT4，OPD 能否把这种新增能力迁移回统一 4B Student；
5. 在数据、更新次数和评测规模充分后，各路线是否进入稳定平台期。

最终结论必须能够区分：

- **模型规模价值**：35B 是否能发现或表达 4B 无法产生的纠错；
- **数据价值**：强对比、失败恢复和购买边界信息是否带来增益；
- **训练范式价值**：相同信息能否被不同规模模型有效吸收；
- **OPD 价值**：多个 Specialist 的能力能否回流到统一 Student；
- **RL 价值**：Student 在吸收新信息后，on-policy 更新是否仍提供额外增益。

## 2. 符号与模型身份

| 符号 | 含义 |
|---|---|
| `R4` | Raw Qwen3.5-4B |
| `R35` | Raw Qwen3.5-35B-A3B |
| `S4` | 当前成熟 SFT Qwen3.5-4B Student |
| `S35` | 使用4B有效SFT范式训练后的 Qwen3.5-35B-A3B |
| `C4` | 使用专项同状态纠错数据继续训练后的4B |
| `C35` | 使用专项同状态纠错数据训练后的35B Specialist |
| `O4` | 从合格 Specialist 经 OPD 更新后的统一4B Student |
| `G4` | 在 `C4` 起点上执行 Student-only on-policy GRPO 后的4B |
| `OG4` | 在 `O4` 起点上执行 Student-only on-policy GRPO 后的4B |

所有不等式都指同一评测协议下的 strict success，而不是训练NLL或不同任务集上的裸点估计。

## 3. 当前已验证事实

### 3.1 35B 可以从正确的 SFT 范式中获益

35B 使用93个自主探索任务、238条重放成功路径和975条训练action row，并迁移4B已验证的逐batch SFT范式后，在冻结96-task、K4环境评测中：

\[
R35=41.406\% < S35=46.615\%
\]

净增为 `+5.208 pp`，task bootstrap 95% CI 为 `[+1.302,+9.635] pp`。因此：

> 35B此前没有提升的主因之一是训练更新方式不合适，而不是35B无法从SFT学习。

### 3.2 当前 SFT4 与 SFT35 统计持平

在独立96-task、K4、相同seed和18/15 horizon资格评测中：

\[
S4=45.573\%,\qquad S35=44.792\%
\]

`S35-S4=-0.781 pp`，95% CI 为 `[-6.510,+5.208] pp`。因此只能表述为：

> 当前SFT4与SFT35统计持平，点估计SFT4略高；当前SFT35尚未取得教师资格。

分项上，S35相对S4为：导航 `-4.688 pp`、匹配 `+1.562 pp`、收尾 `+0.781 pp`。匹配和收尾优势均不足以证明专项教师能力。

### 3.3 当前 SFT4 与 SFT35 不是同任务、同语料对照

当前 `S4≈S35` 是两个完整训练系统的结果比较，不是控制数据后的模型规模比较：

- S4语料来自固定256-task mini-train roster上的Raw4自主采样；两个K8 seed共4096条轨迹，最终保留
  156个strict-success task、493条strict/replay-success轨迹和31,362个completion-label token；
- S35语料来自另一组fresh teacher-train任务上的Raw35自主探索；首批32-task K4与扩展128-task K8
  共1152条轨迹，经fresh replay与每任务路径上限后保留93个task、238条路径，正式训练使用975条
  action row；
- 两者的task identity、source policy、采样seed、K预算、成功覆盖、路径组成、能力分桶和损失权重均不同；
- 两者只在高层语义上同属“public-input、strict-success、fresh-replay-success的completion-only SFT”，
  不能称为同任务产生的相同类型数据。

35B采用“4B有效SFT范式”只表示迁移了逐batch更新、completion-only监督、Raw retention和有界LoRA等
训练思想，不表示S4与S35接受了相同信息。因此当前配对资格结果回答的是：

> 两条各自数据生成与SFT链路完成后，最终S4和S35在未见环境任务上的整体性能是否不同。

它不能单独回答：

- 相同语料下35B是否比4B吸收得更好；
- 相同任务和相同采样预算下Raw35是否能生成比Raw4更高质量的数据；
- 当前差异究竟来自模型规模、语料覆盖、数据质量还是训练配置。

### 3.4 当前不能严格声称 SFT4 超过 Raw35

现有 `R35` 与 `S4` 数值来自不同评测片。即使点估计看起来满足 `S4>R35`，也不能作为正式结论。必须补充同任务、同K、同seed、同horizon的直接配对，才能确认：

\[
S4>R35
\]

在此之前，该关系属于待验证假设。

### 3.5 4B 和35B都缺少高质量纠错与强对比信息

历史4B在线数据中，26个mixed task只有3个含same-item strict-partial对比，2个含option contrast。35B当前SFT语料主要由自身strict-success轨迹构成，能够教“成功时怎么做”，但很少直接回答：

- 在相同失败状态上哪一步错了；
- 同一商品的哪个option应替换；
- 为什么当前购买是partial而不是strict；
- horizon或动作失败后如何恢复；
- 何时应继续搜索，何时应购买并终止。

因此，两种模型共享数据缺口；区别在于S4已经较充分掌握常见模仿模式，而S35还需要证明更大的容量能否把专项数据转化为S4没有的优势。

## 4. 总体基础假设

在公平评测下，期望但尚未全部验证的基础关系为：

\[
R4<R35
\]

\[
R4<S4
\]

\[
R35<S35
\]

在各自不同SFT数据链路完成后，当前观察更接近：

\[
S4\approx S35
\]

研究重点不再是重复证明参数更多，而是先拆分“相同语料吸收能力”和“相同协议自主数据生成能力”，
再观察加入专项纠错信息后，性能关系向哪一条分支演化。

## 5. 可能性A：4B自纠错路线成功，35B非必要

训练链为：

```text
S4
  -> 从4B真实失败状态构造定向分支
  -> 环境筛选strict成功suffix
  -> suffix-only corrective SFT
  -> C4
  -> Student-only on-policy GRPO
  -> G4
```

理想性能关系：

\[
S4<C4<G4
\]

并且：

\[
G4>S35
\]

若成立，说明4B并不缺少完成任务的潜在能力，主要缺少高质量纠错数据和有效的定向探索。此时：

- 35B不是必要教师；
- 正式主链简化为“4B专项数据构造 + 自纠错 + on-policy GRPO”；
- 35B仅作为可选困难状态搜索器，不进入默认部署或训练依赖。

该分支是成本最低、归因最清楚的优先验证路线。

## 6. 可能性B：专项SFT35超过SFT4，OPD成功

先使35B获得可验证的专项能力：

```text
R35
  -> 更高覆盖自主探索
  -> 学生失败状态上的same-state纠错
  -> same-item/option/购买边界强对比
  -> fresh-session strict重放
  -> 专项SFT
  -> C35 Specialist
```

只有当：

\[
C35>S4
\]

且优势在预注册专项能力片上稳定存在，35B才获得OPD教师资格。随后：

```text
多个合格C35 Specialist
  -> 在S4访问到的exact token prefix上给出动作分布
  -> On-policy Distillation回流到统一4B Student
  -> O4
  -> Student-only on-policy GRPO
  -> OG4
```

可能出现：

\[
S4<O4\leq C35
\]

以及：

\[
S4<O4<OG4
\]

若多个Specialist能力互补，并且统一Student通过自身状态分布继续强化，最终也允许出现：

\[
OG4>C35
\]

这并不矛盾：Specialist负责提供分散的新信息，统一Student负责整合，并通过on-policy RL针对目标分布优化。

## 7. 可能性C：35B更强，但OPD迁移失败

可能观察到：

\[
C35>S4
\]

但：

\[
O4\approx S4
\]

甚至：

\[
O4<S4
\]

这时应得出“教师资格成立，但当前OPD迁移方法失败”，而不能说35B无效。潜在原因包括：

- Specialist纠错状态与Student真实访问状态不一致；
- 教师suffix过长或包含4B难以压缩的隐式推理；
- 多Specialist目标冲突；
- token-level蒸馏未对准真正的决策边界；
- Student遗忘原有导航、格式或搜索能力；
- 4B容量不足以同时保留原能力并吸收全部专项能力。

该分支下一步应优化迁移合同，而不是继续扩大教师资格评测。

## 8. 可能性D：4B自纠错与35B OPD均有效

可能同时满足：

\[
C4>S4
\]

和：

\[
O4>S4
\]

此时需要比较净收益、覆盖面与成本。推荐形成分层调用：

```text
普通失败状态      -> 4B自纠错
4B反复失败的难状态 -> 35B Specialist纠错
两类strict纠错数据 -> 统一蒸馏到4B
统一4B             -> Student-only on-policy GRPO
```

可能的最终关系为：

\[
S4<C4<HybridO4<HybridOG4
\]

35B在该路径中不是全程必要组件，而是按需调用的困难状态教师。

## 9. 可能性E：4B和35B进入共同平台期

在数据覆盖、训练更新和评测规模充分后，仍可能得到：

\[
S4\approx S35\approx C4\approx C35\approx O4\approx G4
\]

可能解释为：

1. WebShop当前分布所需能力已接近4B可实现上限；
2. 35B规模优势没有转化为环境动作优势；
3. 两者受到相同的观测、搜索或数据上限约束；
4. 当前LoRA覆盖不足以释放35B routed experts；
5. 合成数据只重复模型已有知识，没有增加新的决策支持；
6. strict评测中的剩余错误主要来自环境歧义或随机性。

此时继续重复同一语料、epoch或seed没有意义。应转向人工/程序化高难样本、更明确的环境反馈或外部高质量轨迹。

## 10. 可能性F：更多训练造成退化

还可能出现：

\[
C4<S4,\qquad O4<S4,\qquad 或\qquad C35<S35
\]

典型原因包括：

- 数据偏向容易成功任务；
- strict成功样本重复过多；
- strong contrast不足；
- 错误教师轨迹被放大；
- 长尾导航与搜索能力被遗忘；
- 更新次数、学习率或LoRA覆盖过强；
- 在线训练只优化局部状态而损害总体分布。

该结果要求停止当前方向，而不是通过增加轮次追平。

## 11. 公平比较合同

“使用相同SFT范式”必须拆成两类实验，不能混为一谈。

当前 `S4(D4)` 与 `S35(D35)` 使用不同任务和不同来源语料，因此不能直接验证模型规模假设。若要回答
“相同数据条件下35B是否优于4B”，**至少必须重新训练一方**；仅重复评测现有两个checkpoint无法消除
数据混杂。

### 11.1 相同数据合成协议，各自生成数据

4B和35B使用相同的：

- fresh task pool和能力分桶；
- 每任务采样次数与总轨迹预算；
- 18/15 horizon；
- 公开信息边界；
- strict与fresh-session replay录取规则；
- same-state、same-item与option contrast定义；
- 任务去重和能力权重；
- train/dev/qualification隔离协议。

但两者各自生成自己的轨迹。该实验比较的是完整的：

> 模型探索能力 + 数据生成能力 + SFT吸收能力。

### 11.2 完全相同轨迹语料，分别执行SFT

将同一份已验证轨迹分别训练4B和35B，并尽量匹配：

- 每任务loss质量；
- effective labeled tokens；
- optimizer update预算；
- retention比例；
- completion-only mask；
- checkpoint选择规则。

该实验比较的是：

> 在信息完全相同的情况下，不同规模模型吸收和泛化这些信息的能力。

两类实验都需要，但结论不同。不能用“各自自探索后的差异”替代“同语料训练效率”，也不能用同语料结果否定大模型在数据生成阶段的价值。

### 11.3 最小必要重训练：固定现有4B语料，只重训35B

最低成本的模型规模验证为：

\[
S4(D4)\quad vs\quad S35(D4)
\]

其中 `D4` 是当前S4已经使用的156-task、493条strict/replay-success轨迹。保留现有 `S4(D4)` 不动，
从Raw35重新训练一个以完全相同 `D4` 为监督信息的 `S35(D4)`。比较时必须使用同一fresh paired评测。

该实验能够回答：

> 在接收相同轨迹信息时，35B是否比4B吸收得更好，并在未见环境任务上形成更高strict success。

它不能回答：

- Raw35是否能自主生成比Raw4更好的数据；
- 35B在不同采样预算下是否具有更高探索效率；
- `D4`是否足以激活35B更大的能力容量。

因此这是模型规模假设的最低成本screen，而不是完整归因。

### 11.4 现有语料的2×2交叉训练

令：

- `D4`：现有Raw4自主生成的SFT4语料；
- `D35`：现有Raw35自主生成的SFT35语料。

构建以下2×2矩阵：

| 训练模型 | `D4` | `D35` |
|---|---|---|
| 4B | 现有 `S4(D4)` | 新训练 `S4(D35)` |
| 35B | 新训练 `S35(D4)` | 现有 `S35(D35)` |

现有模型覆盖对角线，因此需要新增两个交叉训练臂：

1. `S35(D4)`：测量相同4B语料下的模型规模/吸收效应；
2. `S4(D35)`：测量35B自主数据对4B是否具有额外价值。

主要对比为：

\[
S35(D4)-S4(D4) \quad\text{模型规模效应（固定D4）}
\]

\[
S4(D35)-S4(D4) \quad\text{数据来源效应（固定4B）}
\]

\[
S35(D35)-S35(D4) \quad\text{数据来源效应（固定35B）}
\]

四格联合分析还可以判断模型规模与数据来源是否存在交互：例如 `D35`是否只对35B有效，或是否能作为
高价值示范反向提升4B。

但该矩阵仍受现有 `D4/D35` 任务规模和采样合同不同的限制。它比较的是两份现有语料的价值，不是最严格
的“同任务自主合成能力”验证。

### 11.5 严格验证：全新同任务、同协议2×2

若现有语料交叉训练出现明确模型效应或数据效应，再冻结一个从未用于训练或选择的共同任务集 `T*`。
Raw4与Raw35必须在下列条件完全相同的情况下分别生成 `D4*` 与 `D35*`：

- 相同task roster、顺序和能力分桶；
- 相同每任务K、rollout seed数量和总轨迹预算；
- 相同18/15 horizon与采样参数；
- 相同public-only输入与available-action合同；
- 相同strict/fresh-replay录取规则；
- 相同每任务成功路径上限、去重规则和train/dev拆分；
- 相同completion-only标签定义和task/path权重。

随后训练完整四格：

\[
4B(D4^*),\quad 4B(D35^*),\quad 35B(D4^*),\quad 35B(D35^*)
\]

该设计同时识别：

- 固定数据时的模型容量与训练吸收差异；
- 固定模型时的数据生成来源差异；
- Raw35是否更容易发现Raw4未覆盖的成功或纠错支持集；
- 大模型优势究竟来自“生成更好的数据”还是“更好地吸收同一数据”。

只有这一层结果才能支撑强因果表述。前两层只能作为低成本screen和路线选择依据。

### 11.6 训练预算匹配原则

相同语料不意味着4B和35B必须机械使用完全相同的学习率，但必须冻结可比较的训练信息与停止规则：

- 相同train/dev task和labeled action row；
- 相同completion label token定义；
- 相同每task/path/action-row质量权重；
- 相同数据遍历次数与最大重复次数；
- 分别使用训练前冻结的安全学习率与LoRA覆盖，不得根据最终评测反复调参；
- 两者均训练到独立dev NLL和闭环monitor不再产生稳定正增益；
- 报告effective updates、labeled tokens、KL、参数位移和环境性能，不能只说“epoch相同”。

若只匹配optimizer step数而每步看到的信息量不同，不能称为训练预算完全相同；若强行使用同一学习率导致
某一模型明显欠拟合或不稳定，也不能解释为模型容量结论。

## 12. 4B自纠错与35B纠错的直接对照

为了判断35B是否必要，应先进行同状态、同预算的数据生成比较：

| 变量 | 4B自纠错臂 | 35B教师纠错臂 |
|---|---|---|
| 起始状态 | 同一S4公开失败状态 | 完全相同 |
| prefix | 同一Student token/action prefix | 完全相同 |
| remaining budget | 扣除prefix后的相同预算 | 完全相同 |
| 每状态采样数 | 相同 | 相同 |
| 可用动作 | 同一public available actions | 完全相同 |
| 录取 | strict + fresh replay strict | 完全相同 |
| 统计 | corrected task、same-item、option contrast、cost | 完全相同 |
| Student训练 | 相同suffix-only方案 | 相同 |
| 最终评测 | paired fresh dev | 同一评测 |

决策规则：

- 若4B已能产生足量强纠错并带来稳定Student增益，取消默认35B依赖；
- 若35B纠正覆盖率和下游增益显著高于4B，启用35B Specialist OPD；
- 若两者均无法产生强对比，转向环境分支控制、程序化示范或外部数据，不再解释为模型规模问题。

## 13. 专项数据必须包含的信息

下一轮不应只扩大成功轨迹数量，而应提高以下信息密度：

1. **同状态纠错**：从S4真实失败状态开始，保留原失败suffix和成功suffix；
2. **同商品强对比**：成功与失败路径保持相同公开ASIN，主要区别为option或购买时机；
3. **option决策边界**：同一页面至少覆盖一个错误option与一个strict option；
4. **购买边界**：区分继续搜索、补选option、Buy Now和终止；
5. **恢复能力**：动作失败、错误查询、返回搜索和horizon前恢复；
6. **多约束匹配**：属性、价格、商品与option组合约束；
7. **环境验证**：所有正样本必须fresh-session strict replay；
8. **无泄漏**：teacher/student prompt不得包含target ASIN、隐藏答案或内部状态。

## 14. “充分训练”和平台期的定义

充分训练不等于无限增加epoch。平台期必须同时基于训练、数据和未见评测判断。

### 14.1 训练内饱和不是性能饱和

以下现象只能证明优化器已拟合语料，不能证明环境能力饱和：

- train/dev NLL下降变慢；
- adapter参数变化变小；
- retention KL稳定；
- 同一训练任务成功率不再提升。

### 14.2 环境平台期判定

在数据合成协议、任务分布和评测协议冻结后，连续至少两轮满足以下条件，才判定当前路线进入平台期：

- 每轮新增的是独立、去重、具有预定专项覆盖的数据；
- fresh paired dev上的增益低于预注册最小实际增益；
- paired bootstrap CI跨零或明显欠功效时只记为inconclusive；
- net positive flips不再增加；
- partial、zero-score、horizon和schema/action没有结构性改善；
- 增加一轮更新或数据后没有重复出现稳定正增益。

平台期判定后，不再增加相同数据的epoch、seed或K来刷点估计。

## 15. 推荐执行顺序

### 阶段0：补齐公平基线

1. 在同一fresh paired roster上评测 `R4/R35/S4/S35`；
2. 正式确认或否定 `R4<R35` 与 `S4>R35`；
3. 保留当前已经成立的 `R35<S35`，并把当前 `S4≈S35`明确标记为不同数据流水线的结果；
4. 不允许仅通过重复评测现有checkpoint宣称模型规模效应。

### 阶段1：最低成本同语料交叉训练

1. 保留现有 `S4(D4)`；
2. 从Raw35训练 `S35(D4)`，先回答固定D4时的模型规模效应；
3. 资源允许时补充 `S4(D35)`，完成现有语料2×2；
4. 所有四格使用同一fresh paired评测；
5. 若交叉训练结果全部持平，优先转向强纠错数据，不扩大普通strict-success语料轮次。

### 阶段2：有信号后执行全新同任务2×2

1. 只有阶段1出现明确模型效应或数据来源效应，才构建全新共同任务集 `T*`；
2. Raw4与Raw35使用相同K、seed、horizon和录取规则生成 `D4*/D35*`；
3. 完成四格交叉训练并在同一fresh评测上比较；
4. 冻结结论后，不使用该评测继续选择学习率或数据规则。

### 阶段3：优先验证4B定向自纠错

1. 冻结S4真实失败状态；
2. 以受控分支和更高单状态探索预算生成suffix；
3. 检查corrected task、same-item和option contrast覆盖；
4. 通过后执行小规模suffix-only corrective SFT；
5. fresh paired dev确认 `C4>S4`；
6. 只有纠错SFT有效，才执行Student-only GRPO验证 `G4>C4`。

### 阶段4：同状态比较35B的额外信息价值

1. 在与4B完全相同的失败状态、预算和seed schedule上运行S35；
2. 比较4B与35B纠正覆盖率、成本和失败类别；
3. 若35B没有明确优势，停止35B教师路线；
4. 若35B明确更强，构建专项C35并重新资格评测。

### 阶段5：仅在教师资格成立后执行OPD

1. 合格Specialist在S4自己访问的prefix上提供distribution target；
2. OPD只更新统一4B Student；
3. paired monitor确认 `O4>S4` 且安全指标不退化；
4. 再运行Student-only GRPO验证 `OG4>O4`；
5. 最终fresh dev比较 `R4/R35/S4/S35/C4/G4/O4/OG4` 中实际产生的模型身份。

## 16. 最终结果分类

| 最终关系 | 结论 | 决策 |
|---|---|---|
| `S4<C4<G4` 且 `G4>S35` | 4B自主闭环成立 | 取消默认35B依赖 |
| `S4<C35` 且 `S4<O4<OG4` | Specialist + OPD + RL成立 | 保留按需35B教师 |
| `C35>S4` 但 `O4≤S4` | 教师有效、迁移失败 | 优化OPD，不扩大教师训练 |
| `C4>S4` 且 `O4>S4` | 自纠错与OPD互补 | 构建混合路由 |
| 所有路线约等于S4 | 共同平台或数据上限 | 停止重复训练，改变信息来源 |
| 任一路线低于起点 | 遗忘或错误监督 | 立即停止该路线 |

## 17. 研究声明边界

最终报告必须遵守以下边界：

- 未做同任务配对时，不声称 `S4>R35`；
- `S4≈S35`只表示当前评测中统计持平，不表示35B参数无价值；
- 35B只有在S4真实失败状态上产生更多可重放纠错，并带来Student下游增益，才具有教师价值；
- 4B自纠错成功时，可以得出35B对当前链路非必要，但不能外推为所有任务都不需要大模型；
- Specialist更强但OPD失败时，应区分教师能力和迁移方法；
- 训练NLL下降不能替代闭环环境提升；
- 单次小样本点估计只能用于screen，不能宣称最终性能链成立；
- promotion/holdout不得用于任何数据选择、停止决策或超参数调整。

## 18. 总体假设

本轮完整假设最终表述为：

> 首先在公平配对条件下确认Raw与SFT阶段的模型规模和训练收益。随后优先验证4B能否通过学生真实失败状态上的定向自纠错与on-policy GRPO超过当前SFT35；若成功，则35B对当前链路非必要。若4B无法自行产生足量高质量纠错，而经过专项数据训练的SFT35能在相同状态、相同预算下稳定超过SFT4，则由多个合格35B Specialist通过OPD把互补能力回流到统一4B Student，再由Student自行进行on-policy GRPO。所有路线均以fresh paired环境评测判断，并在独立数据和充分更新后性能不再稳定提升时判定平台期，从而分别识别模型规模、专项数据、知识迁移和强化学习的真实价值。

其中，“确认模型规模和训练收益”的最低必要条件是至少新增 `S35(D4)`；完整归因需要现有语料2×2，
强因果结论需要全新共同任务、同合成协议下的 `4B/35B × D4*/D35*` 四格实验。未经这些交叉训练，
当前 `S4≈S35` 只能作为两条不同训练流水线的最终性能观察，不能作为模型容量结论。
